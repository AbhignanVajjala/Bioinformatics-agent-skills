# Quick and Full execution policy

QUICK is the default for a bounded question, preliminary inspection, short
consultation or simple troubleshooting. Answer directly, usually within
200–400 words. Perform essential input, identity, scale, design and evidence
checks. State critical blockers and missing data. Create no mandatory files
unless actual execution requires them or the user requests them.

FULL is the default for an explicitly requested reproducible analysis,
executed workflow, benchmark, complete audit or research handoff. Validate
inputs and design, execute available established software, and record actual
commands, versions, hashes, parameters, exclusions and limitations. Produce
requested outputs and necessary validation evidence. Add a handoff only when
it supports a multi-stage continuation.

Apply the same scientific safeguards in both modes. Never count technical
libraries or cells as independent subjects, replace a confounded estimand with
an identifiable claim, ignore censoring or subject leakage, or claim biological
validation from computation. Replicate minima supply no power guarantee.
Insufficient replication can permit labeled descriptive exploration with
appropriate uncertainty and no population-level confirmatory inference.

Named artifact lists in a skill describe FULL-mode outputs when relevant.
For QUICK, put the necessary checks and conclusions in the response. Preserve
input files and keep generated artifacts within the task's purpose and budget.
Missing runtimes or evidence yield BLOCKED or NOT_RUN. An unsuccessful gate
stays FAIL, with a reason and a recovery action.
